## 独立审查与修复

独立只读审查确认 5 项重要问题，均先补回归测试复现再修复：

1. 新排除文件的历史内容被误当删除发送：区分真实删除和退出检查范围，过滤历史 diff。
2. A → B → A 文件回退仍执行 B：重新核对 A 并替换过时任务。
3. 捕获期间选项变化重入旧范围：观察结束、执行开始和结果保存均核对配置版本。
4. 观察失败后旧任务显示完成：标记过期，不覆盖不可访问状态，不推进成功基线。
5. 同文件两处同类问题丢失：身份加入证据及独立位置序号，验证行号移动后的保留。

另加强实际文件句柄路径核对与有上限的读取，覆盖项目外句柄、超限读取及 Windows junction。动态恶意链接替换尚未做压力测试，不宣称覆盖所有文件系统竞态。

## 验证方式

- `python -m unittest discover -v`：临时真实目录/数据库、本机 HTTP 模型替身、真实 CLI 启动、访问控制、保存触发、失败重试、重启、排除项与任务竞态回归。
- `node --check codescout/web/app.js` 和 Python 编译检查：脚本语法验证。
- 浏览器：实际打开本机网页，填写模型和项目配置，自动生成带关联源码证据的问题；检查报告、项目设置和暂停/恢复流程。
- OS 不允许创建普通符号链接时，该项测试跳过；Windows junction 分支单独执行。

最终结果：40 项测试，39 项通过、1 项因系统不允许创建普通符号链接而跳过，0 失败；Windows junction、项目外句柄及读取上限测试通过。网页脚本语法与 Python 编译检查通过。

浏览器还发现已有页面重新打开新会话令牌时发生同页导航而不重新读取令牌；已增加令牌变化处理，并按失败场景复验。
