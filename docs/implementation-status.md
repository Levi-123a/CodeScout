## 追加修复：复制启动链接仍被拒绝

已在真实 Windows 环境复现：旧服务占用 8765 时，批文件仍打印新链接，但该新令牌访问 `/api/state` 返回 403。原因是标准 HTTP 服务启用地址复用，Windows 允许新旧监听者同时绑定同一端口，请求可到达使用旧令牌的服务。[Windows 套接字行为说明](https://learn.microsoft.com/en-us/windows/win32/winsock/using-so-reuseaddr-and-so-exclusiveaddruse)。

修复为 Windows 绑定前启用 `SO_EXCLUSIVEADDRUSE` 并关闭地址复用。重复启动占用端口立即失败，不再生成不可用的新链接。访问令牌和来源校验继续生效。

- 新增两个回归：同端口的第二个服务必须失败；不同数据目录的第二个 CLI 进程必须退出且不输出新令牌。两项修复前失败、修复后通过。
- 已停止本任务留下的旧版本实例，实际运行 `start.bat` 启动正常版本；用其完整链接打开浏览器、重载后正常显示页面，连续三次认证接口均返回 200。
- 完整 Python 回归 94 项中 92 项通过、2 项因符号链接权限跳过；前端 11 项通过。
- 独立只读审查未发现生产修复的重要问题；Windows 临时端口的“请求完成后关闭并立即重启”等探针通过。审查提出的启动测试超时清理问题已改用有截止时间的读取队列，避免验证过程本身挂住。

## 支持边界

- 当前检查对象是本机工作目录。独立 Git 提交快照、未拉取远程更新检查及远程修复仍未实现。
- 自然语言语义检查和 Agent 修复需兼容的外部模型。真实模型的误报、漏报、修复语义质量、费用与规模性能尚未测量；本机模型替身验证流程及协议。
- Python AST 及 Python/JSON 语法检查已实现；其他语言没有内置编译器，也没有完整语言依赖图。
- 约定和修复保存会进行路径/链接/内容核对及原子替换，无法完全消除不合作外部编辑器在最后核对与替换之间的文件系统竞态。修复失败或部分应用保留记录与备份，不自动回滚。
