# 巡码（CodeScout）开发路线图

日期：2026-10-13。状态：建议，未排期。本文定义阶段成果及验收条件，不是具体实施计划，不承诺交付日期。

依据：[需求文档](requirements.md) 和 [架构设计草案](superpowers/specs/2026-10-13-codescout-design.md)。全部阶段完成并满足第一版验收条件，才构成当前第一版范围。

## 阶段 0：确认产品与设计

成果：明确系统和语言范围、外部模型接口、规范作用域、修复方式及远程监控策略；评审书面设计，之后形成实施计划。

完成条件：已确认要求与建议分开记录，优先决策有明确结果，开发和验收范围可以落到具体样例。当前处于本阶段，文档生成不等于设计已批准。

## 阶段 1：接入与首次检查

成果：本地服务与浏览器界面可管理项目，配置约定和外部模型，自动首次检查，并展示报告、覆盖范围及失败状态。

验收：AC-01、AC-13、AC-14。模型请求实际不可用时不得展示虚假的成功报告。此阶段尚不代表完整持续监控产品。

## 阶段 2：文件与本地 Git 自动检测

成果：保存文件、提交及分支变化后自动安排增量检查；支持上下文关联、约定变化复查、任务去重和报告过期标记。

验收：AC-02、AC-03、AC-05、AC-06、AC-09，以及 AC-12 中的本地状态处理。整个流程无需用户逐次点击检测。

## 阶段 3：远程自动检测与后台恢复

成果：受监控远程目标出现更新时，即使本地未拉取也自动检查；浏览器关闭后继续工作；断网和服务恢复后补查。

验收：AC-04、AC-10、AC-11、AC-12。观察到远程变化但模型检查失败时，未检查变化必须仍然可补查。

## 阶段 4：Agent 修复与复查

成果：按确认的授权流程选择问题、生成和应用修改，保护用户并发编辑，记录验证结果，并复查受影响范围。

验收：AC-07、AC-08、AC-09、AC-13、AC-14。验证失败、取消及部分应用均有准确状态。远程问题修复必须明确目标。

## 阶段 5：第一版整体验收

成果：整理实际运行、配置和故障处理文档，完成受支持范围内的全流程验证与质量评估。

完成条件：AC-01～14 均有证据；三类自动检测、可选修复及恢复机制形成闭环；公开的支持范围与实际实现一致。语义质量指标和性能目标在阶段 0 确定后纳入验收。

## 持续关注的风险与验证

| 风险 | 在哪个阶段验证 | 验证目的 |
| --- | --- | --- |
| 代码与文档关联不足 | 阶段 1～2 | 检查能否发现未出现在 diff 中的相关问题 |
| 漏掉变化或重复检查 | 阶段 2～3 | 证明核对、去重和恢复能够覆盖真实状态 |
| 外部模型成本及不稳定输出 | 阶段 1～5 | 确认预算、失败处理和人工评估可用 |
| 修复覆盖用户修改 | 阶段 4 | 验证源内容核对、冲突和部分应用处理 |
| 不同目标报告混淆 | 阶段 2～4 | 保持工作目录、本地和远程结果可追溯 |

具体任务拆分、负责人、依赖安装、技术选型与工期在设计确认后的实施计划中确定，不在本路线图中提前承诺。
