# 巡码（CodeScout）：需求文档

- 创建日期：2026-10-12
- 更新日期：2026-10-13
- 版本：0.2
- 状态：讨论草案，可用于继续澄清需求；尚未批准进入实现
- 产品名称：巡码（CodeScout）

## 1. 目标与成功标准

帮助开发者持续发现项目与其自行制定的规范之间的偏差，尤其是代码质量问题、注释与实现不一致、文档与代码不同步，并支持用户选择 Agent 修复。

成功标准是：接入项目后，无须用户逐次手动启动检查；文件变化、本地 Git 更新和未拉取的远程新提交能够自动进入检查流程。检查结论可追溯到对应快照和约定，用户能够自主处理问题或选择辅助修复，并看到复查结果。

本产品的规范检查不是“证明项目完全正确”。报告必须明确实际检查范围、未覆盖范围、失败项以及需要人工判断的结论。

## 3. 用户与主要流程

第一版按个人开发者管理自己的本地项目进行设计；是否支持团队协作或共享项目需另行确认。

主要流程：添加项目 → 选择约定 → 自动首次检查 → 持续自动发现变化 → 基于 diff 与相关上下文检查 → 提示问题 → 手动或 Agent 修复 → 复查。

浏览器负责配置、展示与交互；本地服务负责监控和执行任务。关闭浏览器页面不应停止已运行服务的监控。服务是否随系统启动以及支持的系统需另行确认。

## 4. 产品方案与取舍

用户已选择本地服务 + 浏览器界面。在这一形态下，后续细化以以下建议为基础：

| 方案 | 优点 | 代价 | 当前建议 |
| --- | --- | --- | --- |
| 确定性规则检查 + AI 语义检查 | 明确规则的结论可重复；语义检查覆盖文档和代码关系 | 需要协调两类结果及配置 | 推荐，兼顾可靠性和覆盖面 |
| 主要由 AI 理解约定并检查 | 自然语言规范接入直接 | 结论稳定性、成本和误报控制更困难 | 保留为简化方案 |
| 主要使用静态检查器与结构化规则 | 容易验证，计算成本可控 | 对自由文本约定及文档语义的覆盖有限 | 可作为有限功能版本 |

模型接入方式已确定为用户配置外部 API；确定性工具接入范围仍待确认。这里比较的是产品检查方式，不锁定语言、框架或厂商。

## 5. 功能需求

### FR-01 项目接入与管理

- 添加本地文件夹，识别项目根目录及 Git 状态，展示接入结果。
- 支持暂停、恢复和移除监控。移除监控不得删除项目源文件。
- 明确展示监控状态、最近成功检查、运行中任务和失败原因。
- 无 Git 的文件夹如何处理尚待确认；不得显示为具备 Git 监控能力。
- 排除依赖目录、构建产物、二进制文件等不适用检查的文件；允许用户配置排除范围，并展示覆盖范围。

### FR-02 规范与约定

- 用户可以选择或编写项目约定文档，使用自然语言描述规范。
- 支持哪些约定文件名、目录级作用域、结构化规则和优先级见待决策项。
- 每次检查记录使用的约定内容版本。目标快照内的约定取自该快照；外部用户配置记录其单独版本。
- 约定变化必须触发受影响范围的重新检查，不能仅检查约定文档自身。
- 约定互相冲突或表达不明确时，展示冲突和待澄清内容，不静默选择结论。

### FR-03 首次自动检查

- 接入项目后自动创建首次检查，给出进度和覆盖范围。
- 检查规范符合性、代码质量、注释准确性及相关文档一致性。
- 建议以接入时工作目录的稳定快照作为初始检查对象；远程目标另建检查任务。
- 部分文件无法读取、无法解析或检查失败时，保存可用结果，并明确标记未完成部分。

### FR-04 三类变化的自动发现

| 变化来源 | 需要发现的变化 | 检查对象 |
| --- | --- | --- |
| 工作目录 | 保存后的新增、修改、删除、重命名；包括约定文件 | 该轮稳定工作目录快照与其比较基线 |
| 本地 Git | 提交、拉取后的变化、合并、切换分支、变基、重置等导致目标状态变化的操作 | 更新前后目标提交快照的差异 |
| 远程 Git | 配置监控的远程分支出现新提交或历史变化，包含尚未拉取的更新 | 远程目标快照与此前已观察目标的差异 |

- 上述变化无需用户手动点击检查。
- 工作目录连续变化需要合并短时间事件，在稳定快照上检查，避免每次保存都重复发起昂贵任务。
- 远程发现需要后台周期核对；网络恢复和服务恢复时重新核对状态。周期及延迟目标待确认。
- 远程检测不自动合并、切换分支或覆盖当前工作目录。检查快照与修复目标必须分开识别。
- 配置需要监控的远程及分支；具体默认范围尚待确认，不隐含检查远程所有分支。
- “持续自动”以服务运行、文件可访问、远程授权及网络可用为条件。界面展示条件不足及补查状态。

### FR-05 基于 diff 的检查范围

- diff 用于识别变化入口，同时读取相关实现、调用位置、注释、文档和有效约定。
- 例如函数参数发生变化时，检查与该函数相关的说明和使用示例，即使文档没有出现在 diff 中。
- 处理新增、删除、重命名和纯文档修改；比较基线记录在报告中。
- 首次接入、基线不存在或历史改写导致旧基线不适用时，重新建立基线并执行有说明的扩大范围检查。
- 合并提交、跨分支和远程强制更新采用明确的比较策略；不假设每次更新均为单一线性提交。
- 将同一稳定快照产生的重复事件去重。新快照出现时，使旧报告标记为过期或待复查，防止作为最新结果展示。
- 最终快照检查与逐条提交审计不是同一要求；是否保留每个中间提交的独立报告待确认。

### FR-06 问题与通知

- 每条问题包含项目、目标类型、分支或提交/快照标识、文件位置、类型、严重程度、原因、关联约定和修复建议。
- 注释或文档不同步问题给出互相矛盾的相关位置；AI 判断标明不确定性及可供核对的依据。
- 支持查看证据、筛选问题、标记待处理、忽略/误报及已解决。忽略范围与有效期需进一步定义。
- 建议通过网页问题列表及状态提示展示结果；页面关闭时是否发送系统通知待确认。
- 区分新发现、重复发现、已解决、过期以及检测失败；失败不能表现为“无问题”。

### FR-07 用户选择 Agent 修复

- 用户选择问题和修复目标后启动 Agent；自动检测本身不触发修改。
- 建议先生成可查看的修复差异，再由用户应用；是否允许用户预先授权直接修改仍待讨论。
- 记录授权的问题、修改范围、源快照、修改差异和验证结果。
- 应用前核对目标文件是否被用户继续编辑。发生变化时重新检查或提示冲突，不静默覆盖。
- 远程快照上的问题若与当前本地分支不一致，明确提示目标差异。具体修复工作区或分支策略待确认。
- 提交、推送、合并属于独立操作，不作为修复默认附带行为。
- 修复后自动复查原问题及受影响范围；没有执行验证时不得显示为验证通过。
- 修复产生的文件变化同样进入自动监控，并通过快照去重避免循环触发相同修复。

### FR-08 手动修复与结果更新

- 用户自行编辑后，自动检测变化并复查相关问题。
- 只有新快照中的检查支持问题已消失时，才自动将其标记为已解决。
- 取消任务、切换分支、移动文件导致位置失效时，保留历史信息并更新目标状态。

### FR-09 任务与恢复

- 建议任务状态为等待、检查中、完成、部分完成、失败、取消、已被新快照替代。
- 保存项目配置、检查基线、任务状态和问题历史，服务重启后可恢复。
- 远程不可访问、认证过期、模型不可用或解析失败时，提示具体原因，进行有上限的重试，并允许用户处理后恢复。
- 服务恢复时核对工作目录、本地 Git 和远程目标，补查尚未处理的状态差异。
- 不承诺在服务停止期间仍执行实时检查；离线期间每个中间提交是否必须补查独立报告待确认。

### FR-10 外部模型配置

- 用户配置外部模型服务及访问凭据，用于语义检查和 Agent 修复。
- 服务地址、模型标识、凭据及超时等配置字段为建议设计；支持的接口协议和厂商待确认。
- 后台统一发起模型请求；访问凭据不返回给浏览器页面，不写入项目源码、检查报告和普通日志。
- 建议按项目配置可发送的文件范围和排除项，只发送本轮所需的上下文，记录发送范围而非凭据。
- 上下文超限、限流或请求失败时，明确报告未完成范围，不把截断或跳过的检查显示为通过。
- 检查和修复是否使用不同模型、预算限制及配置生效范围待确认。第一版不要求本地模型能力。

## 6. 建议的系统边界与数据流

| 模块 | 职责 | 主要输入与输出 |
| --- | --- | --- |
| 浏览器界面 | 配置项目、展示问题、选择修复和查看差异 | 配置/用户操作 → 服务请求；任务/报告 → 页面 |
| 本地服务与任务调度 | 持久化、排队、去重、取消、恢复 | 变化事件 → 带快照与规范版本的任务 |
| 项目与 Git 观察器 | 发现文件、本地 Git 与远程状态变化 | 项目配置/状态 → 变化事件 |
| 快照与上下文管理 | 确保比较基线、代码及规范一致 | 变化事件 → diff、目标快照、相关文件 |
| 检查引擎 | 执行明确规则及语义检查 | 快照/上下文/约定 → 有依据的问题 |
| 问题管理 | 跟踪新增、重复、过期与解决 | 检查报告 → 问题状态与提示 |
| 修复执行器 | 在用户授权范围内生成及应用修改、复查 | 问题/目标/授权 → 差异、验证与修复结果 |

建议数据流：变化发现 → 核对状态与合并事件 → 固定目标快照 → 计算差异及上下文 → 检查 → 存储报告 → 提示用户。用户选择修复后进入独立修复流程，修复产生新快照再复查。

## 7. 非功能要求（建议，数值待讨论）

- **响应与资源：** 对连续变化进行事件合并、任务去重和并发限制；展示队列和耗时。尚不设定未经验证的延迟保证。
- **稳定性：** 页面关闭不影响服务；服务重启和网络中断后可补查，失败状态可见。
- **可解释性：** 结论可关联到具体规则和源码依据，保留模型/检查器版本及检查范围。
- **本地访问：** 默认限制本地服务访问，并保护配置及修改接口；额外开放网络访问需要单独设计。
- **代码与凭据：** 不在报告、日志或模型输入中泄露访问凭据；代码是否允许发送到外部模型必须由用户明确配置。
- **执行边界：** 仓库内的说明是检查对象；不能借其内容扩大 Agent 修改权限。项目命令及验证执行方式需要明确配置。
- **可取消性：** 耗时检查和修复可取消；保留已产生的可审阅结果及准确状态。

## 8. 验收场景

以下为后续实现的验收依据；需要确定技术范围后转换为具体测试。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 用户添加含约定文档的项目 | 自动首次检查，展示覆盖范围和问题。 |
| AC-02 | 修改函数行为但未更新相关注释和文档 | 保存后自动检查；能定位相关不一致，包含未变化的关联文档。 |
| AC-03 | 本地新增提交、切换分支或变基 | 自动识别目标变化，报告记录比较对象，不混用其他分支快照。 |
| AC-04 | 远程受监控分支更新，本地没有拉取 | 自动发现并检查远程快照；本地工作目录保持用户当前状态。 |
| AC-05 | 连续保存同一文件，并出现重复 Git 事件 | 合并或去重检查，最新有效快照得到报告，过期结果明确标记。 |
| AC-06 | 约定发生变化但业务代码未变 | 自动复查受新约定影响的范围。 |
| AC-07 | 用户选择问题启动 Agent | 修改在所选授权范围内，差异可查看，复查结果可追溯。 |
| AC-08 | 修复期间用户再次修改目标文件 | 不静默覆盖；提示冲突或按新状态重新生成修复。 |
| AC-09 | 用户自行修复问题 | 自动复查后更新状态，不需要手动触发检测。 |
| AC-10 | 浏览器关闭、服务保持运行 | 检测继续，重新打开页面能够看到新结果。 |
| AC-11 | 断网、凭据过期或模型请求失败 | 显示未完成原因；恢复后补查，不误报“检查通过”。 |
| AC-12 | 服务重启或远程历史被改写 | 核对状态并选取有效比较策略；旧基线无效时明确重建。 |
| AC-13 | 用户配置外部模型 API 后开始检查或修复 | 后台使用配置请求模型，仅发送必要上下文；报告及普通日志不包含凭据。 |
| AC-14 | 外部模型限流、请求失败或上下文超限 | 展示失败或部分完成状态及未覆盖范围，允许恢复，不显示为全部通过。 |

## 9. 第一版范围建议

纳入：本地项目接入、约定读取与配置、首次检查、三类变化自动检测、上下文检查、问题管理、用户选择 Agent 修复、复查与任务恢复。

暂不纳入：组织协作平台、多人审批、计费、云端托管、自动提交/推送/合并和本地模型支持。项目数量上限、语言支持范围、远程平台及操作系统尚未确定。
