## 文档维护方式

- 已确认产品要求以需求文档的 C 系列条目及决策记录为准。
- FR 系列条目细化能力；未明确确认的方案仍为建议。AC 系列条目提供后续验收依据。
- 架构和路线图应引用需求编号，不能通过技术设计默默扩大产品范围。
- 决策变更时先更新需求及决策记录，再同步 README、概览、架构和路线图。
- 实现记录区分已经验证的流程、真实模型尚待评估的质量和后续路线图能力。

## 当前已确认

正式名称为巡码（CodeScout）；采用本地后台服务和浏览器界面；自动检测工作目录、本地 Git 和远程尚未拉取的更新；用户自行处理问题或选择 Agent 修复；使用用户配置的外部模型 API，并允许发送必要代码上下文。

## 下一项优先决策

推进本地提交快照与远程独立快照检查；Agent 修复确认方式、远程分支范围、逐提交审计和语义质量指标仍需在相应阶段细化。
