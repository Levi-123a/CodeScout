# 巡码（CodeScout）项目概览

日期：2026-10-13。状态：产品草案。已确认内容以 [需求文档](requirements.md) 为准。

## 产品定位

巡码是一款运行在用户本机的项目规范持续监控工具。它通过浏览器管理本地项目，由后台自动检查代码、注释和文档是否符合用户制定的约定，并在用户选择后提供 Agent 修复。

一句话目标：让项目约定在后续每次变化中持续得到检查，让问题发现、处理和复查有明确依据。

## 面向谁

建议第一版面向维护自己项目的开发者，尤其是使用自然语言约定文档、希望持续保持代码和说明一致的用户。多人协作与组织治理不是当前第一版范围。

## 核心场景

| 场景 | 用户期望 | 对应需求 |
| --- | --- | --- |
| 接入已有项目 | 选定文件夹及约定后自动发现存量问题 | FR-01～03 |
| 日常保存代码 | 无须手动检查就能发现新问题及相关文档偏差 | FR-04～06 |
| Git 提交、合并或切换分支 | 依据实际目标状态检查，报告不混淆分支 | FR-04～05 |
| 远程有更新但未拉取 | 自动发现并查看远程问题，不改动当前工作目录 | FR-04～06 |
| 需要修复问题 | 自行编辑，或选择 Agent 处理后查看复查结果 | FR-07～08 |
| 页面关闭或短暂离线 | 页面关闭后服务继续工作，服务或网络恢复后补查 | FR-09 |

## 第一版价值闭环

配置项目和外部模型 → 自动发现变化 → 基于差异和上下文检查 → 查看有依据的问题 → 选择处理方式 → 验证问题是否解决。

这一闭环必须包含用户明确要求的三类自动检测。分阶段开发可以先验证其中一部分，但只实现本地提交检查不能视为第一版完整交付。

## 范围建议

纳入项目与约定配置、首次检查、持续监控、外部模型接入、问题列表、修复及复查、失败与恢复处理。暂不纳入团队云服务、组织权限、计费、自动提交与推送、本地模型支持。

具体语言、系统、远程平台和项目规模未确定。不能以“代码质量检查”隐含承诺覆盖全部语言或识别所有缺陷；检查类别和覆盖范围需要明确展示。

## 产品原则

1. 后台发现变化并发起检测，不要求用户逐次点击检查。
2. 检查以 diff 为入口，结论建立在对应快照与必要的关联上下文上。
3. 检测状态、检查覆盖范围和问题证据可查看，失败不表现为通过。
4. 自动检测与用户选择修复是两个独立行为。
5. 修复不能静默覆盖用户并发编辑；远程检查不自动合并到本地。

## 评估方式建议

使用受控示例项目验证自动触发、文档关联、远程检查、冲突保护及恢复；另建立有人工标注的问题样例，评估检查误报、漏报和修复效果。记录变化发现延迟、任务耗时、模型调用量和失败率。具体数值目标在确定项目规模与模型后讨论。
