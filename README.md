# 巡码（CodeScout）

本机项目检查工具。后台观察文件变化，分批检查源码、注释、文档和项目约定；网页展示问题、检查范围和修复结果。

当前为 **v0.2 本地预览版**，支持工作目录检查和用户选择的 Agent 修复。本地 Git 提交快照、未拉取的远程提交检查仍未实现。

## 启动

Windows 下双击本目录或上一级目录的 **`start.bat`**。脚本检查 Python 3.11+、SQLite 和文件夹选择器组件，启动服务并打开浏览器。运行产品不需要安装第三方依赖或 Node.js。

- `[CHECK]`：检查运行环境。
- `[START]`：启动服务；成功后显示本机链接。
- `[ERROR]`：显示缺少组件、端口占用或启动失败原因，窗口等待按键。
- 保留服务窗口；按 Ctrl+C 停止。关闭网页不会停止服务。

也可在本目录运行：

```powershell
python -m codescout --open
```

端口被其他程序占用时，可指定端口和数据目录：

```powershell
python -m codescout --open --port 8766 --data-dir .codescout/local
```

默认仅监听 `127.0.0.1:8765`。同一数据目录只允许一个服务实例。重启后使用启动窗口显示的新链接，链接中的令牌用于访问当前会话。

Windows 服务独占监听端口。已有服务占用端口时，新启动会立即报错，不会输出新会话链接；先停止旧服务，或使用上面的 `--port` 参数选择其他端口。

默认数据目录是 `%LOCALAPPDATA%\CodeScout`，包含数据库 `state.db` 和修复备份 `repair-backups`。数据库保存项目文本、报告和模型配置；密钥目前保存在本机数据库，不返回给网页，尚未接入系统凭据保险库。

## 接入与检查

1. 点击“模型设置”，填写兼容 Chat Completions 的 API 基础地址、模型名称和密钥。基础地址填到 `/v1` 等前缀，服务会附加 `/chat/completions`。外部服务使用 HTTPS；本机测试服务可使用 HTTP。
2. 点击“接入项目”，在电脑上的文件夹选择窗口选定项目。取消选择不会接入。
3. 设置排除路径、项目约定、可选验证命令，并选择是否允许把必要的项目内容发送到模型。项目列表和标题显示文件夹名，完整路径可展开查看。
4. 允许发送且模型已配置后，后台自动首次检查。保存文件、修改约定或模型配置后自动复查。可暂停、恢复或重新检查。
5. 在“问题”中查看位置、真实源码引文、关联证据、约定和建议；在“检查记录”中查看批次进度、实际行段、排除原因和未覆盖范围。

检查范围详情保持展开，直到主动关闭；状态轮询、报告更新和页面重载会保留展开状态。移除项目监控不会删除项目源文件。

## 附加约定

约定保存在项目根目录的独立文件 **`CODESCOUT_RULES.md`**。在“项目设置”保存内容会写入该文件；也可直接用编辑器修改，后台会重新读取并复查。浏览器保存前核对原内容，避免覆盖外部编辑。

`AGENTS.md`、`CLAUDE.md` 只作为写法参考，不自动作为本工具的约定来源，也不在 agents 或 Claude 文件夹中保存约定。旧版存于数据库的约定会提示在项目设置中明确保存到新文件，不会自动写进仓库。

约定宜短而具体，例如：

```markdown
# 项目检查约定

- 函数的参数、返回值发生变化时，同步更新注释和 README 示例。
- 异常处理需说明失败原因，不能把执行失败显示为成功。
```

约定文件须为 UTF-8，最多 20,000 字符；如果超过单次请求预算，检查明确失败，需要缩短内容。

## Agent 修复

1. 对未过期的待处理问题点击“生成修复”。模型通过 `read_file` / `search` 工具按行读取和定位源码，再生成精确替换及差异预览。模型须支持 Chat Completions 工具调用。
2. 查看差异及读取记录。此时没有写入源文件。
3. 点击“应用修改”。服务核对文件哈希，保留原文件备份，再写入修改；并发编辑或越界路径会停止应用。修改范围限于该问题及其引用文件。
4. 校验实际文件的 Python / JSON 语法；如果配置了验证命令，在项目目录真实执行该命令，记录输出、退出码和超时。随后自动复查问题。

验证命令是单条程序及参数，不经过 shell；例如 `python -m unittest discover`。最长执行 60 秒，超时终止命令及子进程，输出最多保存 8 KiB。未配置命令时明确显示“未运行项目测试”。验证失败不会回滚修改；部分应用会显示已改文件，原内容保存在备份中。服务中断后不会自动继续写源码。

## 检查预算与覆盖

- 每 2 秒观察工作目录，稳定 1 秒后排队；同一快照和配置去重，任务串行执行。
- Git 项目遵循忽略规则；无 Git 文件夹也可接入。默认排除依赖、构建、凭据、锁文件、压缩产物、二进制、链接和本工具临时数据，详情说明原因。
- 单文件最多 256 KiB，快照最多 8 MiB / 2,000 文件，仅支持 UTF-8 文本。
- 首次检查逐文件、逐行段发送。每批主文件最多 120 行，关联片段最多两个文件、各 30 行；完整序列化输入受 `min(配置预算, 12,000)` 字符限制，包含约定和协议开销。字符预算不是 token 预算。
- 不一次发送全部文件。超长单行、超限文件和读取失败明确列为未覆盖；不会把截断视作完整检查。
- 每个成功批次立即保存进度。同一快照和配置的失败或中断检查从已完成批次继续；新配置需要重新检查。
- 增量检查优先检查变化及关联文件。只有原完整覆盖且配置一致时才沿用未变化文件的结果；问题还须核对所有引用文件的完整内容。界面明确标注“沿用”，与本次重新检查区分。
- Python AST 提供语法问题和符号线索；模型问题须通过文件、真实行号和源码引文校验。不存在完整跨语言依赖图。
- 请求失败最多按 5、30、120 秒重试三次；失败、部分完成和过期不会显示为通过，也不会自动解决未检查的旧问题。

真实外部模型的误报、漏报、费用和修复语义质量尚需人工样例评估。测试模型仅验证流程和协议。
