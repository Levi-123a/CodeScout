# 项目规范持续监控工具（暂定名）

一个通过本地后台服务和浏览器界面，持续检查项目代码、注释、文档是否符合用户约定的工具。用户接入项目后，检查自动触发；发现问题后，用户可以自行处理，也可以选择 Agent 辅助修复。

> 当前处于需求讨论阶段，仓库尚无产品实现。本文描述计划中的行为，并非已上线功能。详细要求见 [需求文档](docs/requirements.md)。

## 为什么要做

项目中的规范不仅包括代码格式，还包括设计约定、注释准确性、文档与实现的一致性。一次性检查很容易随着后续修改而过时。本工具希望让这些约定持续受到检查，并帮助用户完成“发现问题—选择处理方式—验证修复”的闭环。

## 已确认的产品方向

- **使用形式：** 本地后台服务 + 浏览器管理界面。
- **项目接入：** 用户选择本地项目文件夹，配置该项目的规范和约定。
- **用户规范：** 支持类似 `CLAUDE.md`、`AGENTS.md` 的约定文档；具体格式和冲突优先级继续讨论。
- **首次检查：** 接入时自动检查项目的有效文件，识别规范违反、代码质量问题、注释和文档不同步等问题。
- **持续自动检测：** 覆盖文件保存后的未提交变化、本地 Git 历史变化，以及本地尚未拉取的远程新提交。
- **增量检查：** 以变化的 diff 为入口，读取必要的关联代码、注释、文档和约定。
- **问题提示：** 提供位置、原因、关联约定和处理建议，并说明检查的是工作目录、本地提交还是远程提交。
- **可选修复：** 用户可以手动修改，或选择问题后使用 Agent 修复；检测发现问题本身不会自动授权修改。

## 预期使用流程

1. 启动本地服务，打开浏览器管理界面。
2. 添加项目文件夹，选择约定文档，配置需要监控的远程仓库及分支。
3. 系统自动执行首次检查，展示问题及检查覆盖范围。
4. 服务运行期间，系统自动发现文件、本地 Git 和远程 Git 的变化并安排检查。
5. 用户查看问题，自行修复或选择 Agent 修复。
6. 系统检查修复后的结果，更新问题状态，并继续监控后续变化。

浏览器页面关闭后，本地服务仍应继续监控。远程检查使用独立快照，不要求用户先拉取，也不自动合并或切换用户的工作目录。服务停止期间不执行检测；恢复运行后核对状态并补查遗漏变化。

## 检查与修复原则

- **自动触发：** 不要求用户在每次 Git 更新后点击检查按钮。
- **上下文一致：** 使用目标变化对应的代码和约定版本，不把不同分支或快照混在同一结论里。
- **证据可查看：** 展示发现问题的依据；不确定的语义判断允许用户复核。
- **修改可审阅：** Agent 的修改范围、差异和验证结果应可查看；具体应用方式仍待讨论。
- **保护用户工作：** 修复不能静默覆盖用户并发编辑；提交、推送和合并需要单独的明确操作。
- **结果可追踪：** 保存检查对象、规范版本、问题状态和修复结果。

## 第一版拟定范围

本地项目管理、用户约定管理、首次检查、三类变化的自动增量检查、问题列表、Agent 可选修复、修复复查，以及断网或服务重启后的恢复处理。

团队云平台、组织权限、计费、自动合并与自动推送暂不纳入第一版。支持的操作系统、编程语言、模型接入方式和远程 Git 平台尚待确认。
